# Instructions for AI agents (Claude Code, Copilot, Cursor, etc.)

You maintain the content of the AGA research-group website. The site is static; **all content is Markdown
files in `content/`**. You almost never need to edit code. Read [guide/STRUCTURE.md](guide/STRUCTURE.md) once for the model.

## Golden rules
1. **One file per item**, in `content/<kind>/<id>.md`, `<kind>` ∈ `lines|people|projects|papers|events|conferences`.
   `<id>` = lowercase ASCII, digits, hyphens (strip accents: `Pérez` → `perez`). Never rename an existing id without updating every reference (`grep -r "<id>" content data`).
2. **Start from `content/_templates/<kind>.md`.** Remove comments and optional fields you have no data for. Never invent data (emails, ORCID, DOIs, dates, affiliations). Omit unknown fields.
3. **Relations are declared once, on the child:**
   - paper → `projects:` (**required**, existing project ids)
   - conference → `event:` (**required**, existing event id); optional `projects:`
   - project → `people:` ; paper/conference → `authors:`
   - Group members in `authors:` use their person **id**; external authors use their plain full name (`Jane Doe`).
   If a paper's project or a conference's event does not exist, create that project/event file first.
4. **Create people before items that reference them** (or use plain names if they aren't members).
5. **Files**: photos → `assets/img/people/`, project images → `assets/img/projects/`, event images → `assets/img/events/`, CVs → `assets/cv/`, PDFs/slides → `assets/papers/`. The frontmatter value is the bare file name. Never reference a file you did not actually add. If you only have a URL, use the full `https://` URL for `cv`, `pdf`, `slides`.
6. **Frontmatter syntax** (simple subset, not full YAML): `key: value` on one line; lists as `[a, b]` or `- item` lines; no multi-line values, no nesting. Dates `YYYY-MM-DD`. ORCID as bare id. `links:` entries are `Label | https://url`. Values containing `:` followed by space are fine; quote with `"..."` if they start with `[`.
7. **Media:** GIFs/videos go in `assets/media/` (or use a YouTube/Vimeo/`.mp4` URL). Use the `video:` field for a main video; inside a body put `![alt](file.gif)` or a bare video URL on its own line. They autoplay muted and loop automatically; don't add HTML.
8. Research line ids come from `data/site.json → researchLines`. Do not invent new ones without being asked; if needed add to that file.
9. Write content in the language the source provides (default Spanish). Body supports minimal Markdown only (headings, lists, bold, italic, links).

## Translations (es is the main language; en, de, fr are generated)
After adding or changing an item, offer/do the translations: create `content/<kind>/<id>.<lang>.md` for `en`, `de`, `fr` (format in `content/_templates/translation.md`).
Translate only `title`/`name`, `summary`/`description`, `position`, `type`, `status`, `funding`, `location`, `abstract` and the body. Keep proper nouns, acronyms, DOIs and venue names unchanged; use natural academic register. UI strings are in `data/i18n.json` (keep all four languages in sync when adding a key).
Missing translations are not an error (they fall back to Spanish), so list which items remain untranslated when you finish.

## Workflow
```bash
# 1. create/edit files in content/ (+ assets)
node src/build.mjs        # 2. validate + build; MUST print "Built …" with no errors
```
The build prints precise errors (`content/papers/x.md: unknown project id "y"`). Fix them and rebuild until clean.
Optionally `npm run serve` and check the page. The generated site lives in `docs/` and **is committed** (GitHub Pages serves it): always run the build before committing so `docs/` matches `content/`.

## Recipes
- **Add a person:** copy `_templates/person.md` → `content/people/<name-surname>.md`; set `name`, `surname` (+ whatever is known).
- **Add a paper from a citation/BibTeX/DOI:** id `<firstauthorsurname>-<year>-<keyword>`; map authors to person ids when they match files in `content/people/` (match by surname + initial, and ask if ambiguous), otherwise full names; set `venue`, `year`, `doi`; choose `projects:` from `content/projects/` by topic (ask if unclear rather than guessing).
- **Add an event with talks:** create the event, then one conference file per talk with `event: <event id>`.
- **Bulk import:** generate one file per row; run the build after the batch; report any rows skipped for missing required data.
- **Remove an item:** delete its file, then rebuild; fix any "unknown id" errors from items that referenced it.

## Don't
- Don't hand-edit `docs/`; it is generated by the build (the human guides are in `guide/`).
- Don't add dependencies or change `src/build.mjs` for content tasks.
- Don't fabricate placeholder entries to "fill" empty sections; empty sections simply don't render.
